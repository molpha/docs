Your contract receives an **attestation** (a signed payload plus one aggregate signature) and checks it on-chain. You don't run a node, trust a relayer, or deploy a feed contract per chain. The same attestation works on every chain below.

<Tabs>
  <Tab title="EVM">
    Install the interface with Foundry:

    ```sh
    forge install molpha/evm-verifier
    echo "@molpha/evm-verifier/=lib/evm-verifier/src/" >> remappings.txt
    ```

    Call `verify` and apply your own policy:

    ```solidity
    import {IVerifier} from "@molpha/evm-verifier/interfaces/IVerifier.sol";

    error NotVerified(uint8 code);

    function settle(IVerifier.Attestation calldata att) external {
        (bool ok, uint8 code) = VERIFIER.verify(att, 60); // maxAge in seconds
        if (!ok) revert NotVerified(code);
        require(att.payload.sourceId == EXPECTED_SOURCE_ID, "wrong source");
        require(att.payload.signaturesRequired >= MIN_SIGNATURES, "threshold too low");
        // guard replay, then decode att.payload.value
    }
    ```

    `verify` returns `(false, code)` instead of reverting, so always check `ok`. Full guide, consumer library and result codes: [Verify on EVM](/verifiers/evm).
  </Tab>

  <Tab title="Starknet">
    Call the Cairo verifier through its dispatcher:

    ```cairo
    use verifier::interface::{Attestation, IVerifierDispatcher, IVerifierDispatcherTrait};

    let (ok, _code) = IVerifierDispatcher { contract_address: verifier }.verify(attestation, 60);
    assert(ok, 'molpha: not verified');
    assert(attestation.payload.source_id == EXPECTED_SOURCE, 'molpha: wrong source');
    assert(attestation.payload.signatures_required >= MIN_SIGNATURES, 'molpha: low threshold');
    ```

    Full guide: [Verify on Starknet](/verifiers/starknet).
  </Tab>

  <Tab title="Solana">
    Read the latest value from a `Feed` account that a submitter keeps up to date, after checking its address:

    ```rust
    #[account(
        seeds = [b"molpha_feed", source_id.as_ref(), &[signatures_required], submitter.as_ref()],
        bump,
        seeds::program = MOLPHA_PROGRAM_ID,
    )]
    pub molpha_feed: AccountInfo<'info>,
    ```

    Or verify an attestation directly in your program with the `molpha-verifier` crate. Both patterns, with a staleness guard: [Verify on Solana](/verifiers/solana).
  </Tab>
</Tabs>

## Get an attestation to test with

Request one from a backend with the [SDK](/quickstarts/backend) or from an agent with [MCP](/quickstarts/ai-agents). The SDK builds the calldata for you:

```ts
import { buildEvmVerifierArgs, buildStarknetVerifierArgs } from "@molpha/sdk";

const evmArgs = buildEvmVerifierArgs(attestation, { maxAge: 60 });
const starknetArgs = buildStarknetVerifierArgs(attestation, { maxAge: 60 });
```

Verifier addresses for each network are on [Deployments](/verifiers/deployments).

## Before you ship

Verification proves that enough selected nodes signed this exact payload. Your contract still owns the rest:

- Pin the `sourceId` you expect and require a **minimum** `signaturesRequired`.
- Enforce freshness: a non-zero `maxAge` on EVM and Starknet, or compare `timestamp / 1000` with the chain clock.
- Reject replays when an old attestation could be submitted twice.
- Decode `value` with the source's encoding and bound-check it.

The full list is the [consumer checklist](/verifiers/overview#consumer-checklist).
