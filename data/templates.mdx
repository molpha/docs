Generated from the service's `GET /v1/catalog`. Each template has a typed endpoint, an MCP tool, and can be read through `POST /v1/read` by id. Every template also takes `finality` (`final` by default, `fast`, or a raw mode) and the [signed-read options](/data/signed-reads).

## Chain

### Pinned block

`chain.head@1` · Chain · head block or slot · evm, starknet, svm chains

The block (EVM, Starknet) or slot (Solana) a source of this chain and finality reads at, from the source format's $block.

**Endpoint:** `GET /v1/{chain}/blocks/head` · **MCP tool:** `get_chain_head`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |

**Returns:** the block number or slot (uint256; int256 on Solana, 0 decimals).

**Caveats:**

- EVM and Starknet: the newest block that satisfies the finality at the round timestamp; its time is about the round timestamp minus the finality's lag. The source format has no block-time leaf.
- Solana: the slot of the node's read, signed as the median of the nodes' slots (tolerance mode).

```bash
curl "https://data.molpha.io/v1/ethereum/blocks/head"
```

## DEX

### Curve EMA price oracle

`curve.priceOracle@1` · DEX · on-chain TWAP and EMA · evm chains

A Curve pool's exponential moving average price (price_oracle) of coin i+1 in coin 0.

**Endpoint:** `GET /v1/{chain}/curve/{pool}/price-oracle` · **MCP tool:** `get_curve_oracle_price`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `pool` | yes |  | a Curve pool with price_oracle (stableswap-ng, crypto, tricrypto). |
| `index` | no |  | for pools whose price_oracle takes an index (stableswap-ng, tricrypto): the coin priced is coins(index+1); omit for two-coin crypto pools. |

**Returns:** coin 0 units per one priced coin, 18 decimals (uint256); Curve scales it to 18 decimals whatever the coins' decimals.

**Caveats:**

- An EMA lags the spot price by design; its half-life is the pool's ma_exp_time.
- For ETH pools coin 0 can be the native-ETH placeholder 0xeeee…eeee.

```bash
curl "https://data.molpha.io/v1/ethereum/curve/0x21e27a5e5513d6e65c4f830167390997aa84843a/price-oracle"
```

### Pool spot price

`dex.pool.price@1` · DEX · spot price as a decimal · evm, svm chains

A concentrated-liquidity pool's current price from its square-root price, adjusted for both tokens' decimals.

**Endpoint:** `GET /v1/{chain}/pools/{pool}/price` · **MCP tool:** `get_pool_price`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `pool` | yes |  | a Uniswap v3-style pool (Uniswap, PancakeSwap, Sushi v3, Aerodrome Slipstream) or an Orca Whirlpool. |
| `invert` | no | `false` | false: token1 per token0 (token B per token A); true: the inverse. One of: `false`, `true`. |

**Returns:** quote-token units per one base token, 18 decimals; the base is token0 (token A) unless inverted.

**Caveats:**

- A spot price moves within a block and can be pushed by a single trade; use dex.pool.twap or a liquidity floor for settlement.
- The price names its quote token. There is no USD conversion.
- Solana pools are written every slot, so the Solana form runs in tolerance mode (median of node reads).
- Prices below 1e-18 of the quote token round to zero; use invert.

```bash
curl "https://data.molpha.io/v1/ethereum/pools/0x88e6a0c2ddd26feeb64f039a2c41296fcb3f5640/price"
```

### Pool reserve

`dex.pool.reserves@1` · DEX · reserves · evm, svm chains

One side of a pool's reserves: getReserves of a Uniswap v2-style pair, the token balance of a v3-style pool, or a Whirlpool's token vault.

**Endpoint:** `GET /v1/{chain}/pools/{pool}/reserves` · **MCP tool:** `get_pool_reserve`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `pool` | yes |  | a v2 pair, a v3-style pool, or an Orca Whirlpool. |
| `side` | no | `0` | token0 (A) or token1 (B). One of: `0`, `1`. |
| `kind` | no | `v3` | EVM: the pool's interface. One of: `v2`, `v3`. |

**Returns:** the reserve in whole tokens of that side (uint256; int256 on Solana, tolerance mode).

**Caveats:**

- v3 and Whirlpool reserves are token balances: they include fees not yet collected and, for v3, tokens sent to the pool by mistake. They are not the liquidity at the current price.
- v2 reserves are as of the pair's last sync.

```bash
curl "https://data.molpha.io/v1/ethereum/pools/0xb4e16d0168e52d35cacd2c6185b44281ec28c9dc/reserves?kind=v2"
```

### Pool state snapshot

`dex.pool.snapshot@1` · DEX · pool state · evm, svm chains

A concentrated-liquidity pool's state under one signature: square-root price, tick, active liquidity and fee (Uniswap v3 family), or the Whirlpool account up to its fee growth.

**Endpoint:** `GET /v1/{chain}/pools/{pool}` · **MCP tool:** `get_pool_snapshot`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `pool` | yes |  | a Uniswap v3-style pool or an Orca Whirlpool. |

**Returns:** keccak256 of the raw payload (bytes32); the payload and its layout come with the response and are decoded into fields.

**Caveats:**

- Exact mode: a pool traded between the nodes' reads fails the round. Whirlpools are written nearly every slot, so the Solana form is best effort; use dex.pool.price (tolerance) for a price.

```bash
curl "https://data.molpha.io/v1/ethereum/pools/0x88e6a0c2ddd26feeb64f039a2c41296fcb3f5640"
```

### Pool TWAP (mean tick)

`dex.pool.twap@1` · DEX · on-chain TWAP and EMA · evm chains

The arithmetic mean tick over a window, from the pool's own oracle (observe), rounded as Uniswap's OracleLibrary rounds.

**Endpoint:** `GET /v1/{chain}/pools/{pool}/twap` · **MCP tool:** `get_pool_twap`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `pool` | yes |  | a Uniswap v3-style pool with an observation buffer. |
| `window` | no | `1800` | seconds, 1 to 86400. |

**Returns:** the mean tick over the window ending at the pinned block (int256, 0 decimals); price = 1.0001^tick, adjusted for decimals.

**Caveats:**

- The pool must hold observations as old as the window, or every read fails.
- The signed value is the tick; converting it to a price needs a power the source format does not have yet (Phase 2). The response shows the price computed from the signed tick.

```bash
curl "https://data.molpha.io/v1/ethereum/pools/0x88e6a0c2ddd26feeb64f039a2c41296fcb3f5640/twap"
```

### Median price across pools

`price.median@1` · DEX · multi-pool price · evm, svm chains

The median price of a token in a quote token across two to four concentrated-liquidity pools of that pair, optionally refusing pools below a liquidity floor.

**Endpoint:** `GET /v1/{chain}/tokens/{token}/price` · **MCP tool:** `get_median_price`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `token` | yes |  | the token priced (base). |
| `quote` | yes |  | the token it is priced in. |
| `pools` | yes |  | 2 to 4 Uniswap v3-style pools, or Solana Orca Whirlpool and Raydium CLMM pools (mixed), of exactly this pair. |
| `minLiquidity` | no |  | every pool's active liquidity (raw units) must be at least this, or the round fails; on EVM at most 2 pools then (liquidity is a second read). |

**Returns:** quote-token units per one token, 18 decimals (uint256; int256 on Solana, tolerance mode).

**Caveats:**

- The median is taken over the pools' square-root prices, then squared: for an even count it is the square of the mean of the two middle square roots, a hair below the mean of the two middle prices.
- A pool below the floor fails the whole round; nothing is signed without it.
- No USD: the price names its quote token.

```bash
curl "https://data.molpha.io/v1/ethereum/tokens/0xc02aaa39b223fe8d0a0e5c4f27ead9083c756cc2/price?pools=0x88e6a0c2ddd26feeb64f039a2c41296fcb3f5640,0x8ad599c3a0ff1de082011efddc58f1908eb6e6d8,0xe0554a476a092703abdb3ef35c80e0d76d32939f&quote=0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48"
```

## Lending

### Aave v3 reserve rate or index

`lending.aave.reserve@1` · Lending · reserve rates and indexes · evm chains

One of an Aave v3 (or Spark) reserve's current rates or indexes, from Pool.getReserveData.

**Endpoint:** `GET /v1/{chain}/lending/{market}/markets/{asset}` · **MCP tool:** `get_aave_reserve`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `market` | no | `aave-v3` | the lending market. One of: `aave-v3`, `spark`. |
| `asset` | yes |  | the reserve's underlying token. |
| `field` | no | `supplyRate` | supplyRate and variableBorrowRate are yearly rates (APR, not compounded); the indexes grow from 1. One of: `liquidityIndex`, `supplyRate`, `variableBorrowIndex`, `variableBorrowRate`. |

**Returns:** a fraction with 27 decimals (uint256): 0.05 is a 5% yearly rate; an index is the accrued growth factor.

**Caveats:**

- Rates are stored at the reserve's last interaction and are yearly rates, not APY.
- A token that is not a reserve of the market fails the source's assertion (liquidity index above zero) instead of signing zero.

```bash
curl "https://data.molpha.io/v1/ethereum/lending/{market}/markets/0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48"
```

### Aave v3 reserve totals

`lending.aave.totals@1` · Lending · totals and utilization · evm chains

An Aave v3 (or Spark) reserve's total supplied (aToken supply) or borrowed (variable debt token supply), or its utilization.

**Endpoint:** `GET /v1/{chain}/lending/{market}/markets/{asset}/totals` · **MCP tool:** `get_aave_totals`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `market` | no | `aave-v3` | the lending market. One of: `aave-v3`, `spark`. |
| `asset` | yes |  | the reserve's underlying token. |
| `field` | no | `utilization` | supplied and borrowed in whole tokens; utilization = borrowed / supplied. One of: `supplied`, `borrowed`, `utilization`. |

**Returns:** supplied and borrowed: whole tokens at the asset's decimals; utilization: a fraction, 18 decimals (uint256).

**Caveats:**

- The aToken and debt token addresses are read when the source is derived and written into it; a reserve that is ever re-deployed gets a new sourceId.
- Borrowed counts variable debt only; stable debt is deprecated in Aave v3.2 and later.

```bash
curl "https://data.molpha.io/v1/ethereum/lending/{market}/markets/0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48/totals"
```

## Oracle

### Two oracle prices compared

`oracle.compare@1` · Oracle · cross-check · evm chains

The deviation between two price feeds on one chain (Chainlink aggregators or Pyth price feeds), refusing a feed older than maxAge; or whether they agree within a bound.

**Endpoint:** `GET /v1/{chain}/oracles/compare` · **MCP tool:** `compare_oracles`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `a` | yes |  | "chainlink:&lt;aggregator or proxy>" or "pyth:&lt;price feed id>". |
| `b` | yes |  | the second feed, in the same form. |
| `maxAge` | no | `86400` | seconds; a feed updated longer ago than this before the round fails it. |
| `maxDeviationBps` | no |  | set it to sign a yes/no answer (deviation within the bound) instead of the deviation. |

**Returns:** the deviation \|a - b\| / min(a, b) in basis points, 2 decimals (uint256); with maxDeviationBps, true when within it (bool).

**Caveats:**

- Both feeds must price the same pair in the same quote; the service shows Chainlink's description, but cannot read what a Pyth id names on chain.
- Pyth prices on EVM are pull-based: a feed nobody updated is refused by maxAge rather than compared.

```bash
curl "https://data.molpha.io/v1/base/oracles/compare?a=chainlink:0x71041dddad3595f9ced3dccfbe3d1f4b0a16bb70&b=pyth:0xff61491a931112ddf1bd8147cd1b641375f79f5825126d665480874634fd0ace"
```

### Aave v3 distance to liquidation

`position.aave.liquidationDistance@1` · Position · distance to liquidation · evm chains

How far an account's collateral value can fall, debt unchanged, before the position can be liquidated: 1 - 1/healthFactor.

**Endpoint:** `GET /v1/{chain}/lending/{market}/positions/{user}/liquidation` · **MCP tool:** `get_aave_liquidation_distance`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `market` | no | `aave-v3` | the lending market. One of: `aave-v3`, `spark`. |
| `user` | yes |  | the account. |

**Returns:** a fraction, 18 decimals (int256): 0.25 means a 25% fall in all collateral; 0 or below means liquidatable now; 1 means no debt.

**Caveats:**

- All collateral is assumed to fall together and debt to stay put; a position with several assets can reach liquidation sooner through one of them.
- An account with debt and no collateral reads 0.

```bash
curl "https://data.molpha.io/v1/ethereum/lending/{market}/positions/0xedfa9614cb7c2b52b5180294d7736abb50dfbac1/liquidation"
```

### Morpho Blue health factor

`position.morpho.health@1` · Position · health factor · evm chains

A borrower's health on a Morpho Blue market, computed as Morpho computes it: collateral at the market's oracle price times LLTV, over the borrow assets of the borrower's shares.

**Endpoint:** `GET /v1/{chain}/lending/morpho/markets/{id}/positions/{user}` · **MCP tool:** `get_morpho_health_factor`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `id` | yes |  | the market id. |
| `user` | yes |  | the borrower. |

**Returns:** maximum borrow over borrowed, 18 decimals (uint256): below 1 the position can be liquidated; 10^18 means no debt.

**Caveats:**

- Three reads at one block: the position, the market (to turn borrow shares into assets, rounded up as Morpho does) and the oracle price.
- Borrow assets are as of the market's last interaction; interest accrued since is not included, so the health is slightly optimistic on an idle market.

```bash
curl "https://data.molpha.io/v1/ethereum/lending/morpho/markets/0xb323495f7e4148be5643a4ea4a8221eef163e4bccfdedc2a6f4696baacbc86cc/positions/0x0000000000000000000000000000000000000001"
```

## Token

### Bridged supply against its lockbox

`supply.reconcile@1` · Token · supply reconciliation · evm chains

A canonical token's balance locked in a bridge, less the total supply of its bridged copies on up to three other chains.

**Endpoint:** `GET /v1/{chain}/tokens/{token}/reconcile` · **MCP tool:** `reconcile_supply`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `token` | yes |  | the canonical token on this chain. |
| `lockbox` | yes |  | the bridge contract that holds the locked tokens. |
| `remote` | yes |  | the bridged copies, "chain:token" comma-separated, 1 to 3 (EVM, Starknet or Solana chains this service serves). |
| `result` | no | `delta` | delta = locked - bridged supply; ok = delta >= 0. One of: `delta`, `ok`. |

**Returns:** delta in whole tokens at the largest of the legs' decimals (int256), or ok (bool); a negative delta means more bridged supply than locked.

**Caveats:**

- Each leg is read at its own chain's finality, so the legs are not one instant: tokens in flight between chains show as a delta.
- A Solana leg reads a mint that moves between slots; a source with one runs in tolerance mode and can only sign the delta.

```bash
curl "https://data.molpha.io/v1/ethereum/tokens/0x7f39c581f595b53c5cb19bd0b3f8da6c935e2ca0/reconcile?lockbox=0x9de443adc5a411e83f1878ef24c3f52c61571e72&remote=base:0xc1cba3fcea344f92d9239c08c0568f6f2f0ee452"
```

`token.snapshot@1` · Token · supply and control flags · evm, starknet, svm chains

A token's supply and decimals (EVM, Starknet) or its whole SPL mint (supply, decimals, mint and freeze authorities) under one signature.

**Endpoint:** `GET /v1/{chain}/tokens/{token}` · **MCP tool:** `get_token_snapshot`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `token` | yes |  | the token: ERC-20 contract, Starknet contract, or SPL mint. |

**Caveats:**

### Token total supply

`token.supply@1` · Token · total supply · evm, starknet, svm chains

The total supply of a token, in whole tokens, read from the token contract or the SPL mint.

**Endpoint:** `GET /v1/{chain}/tokens/{token}/supply` · **MCP tool:** `get_token_supply`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `token` | yes |  | the token: ERC-20 contract, Starknet contract, or SPL mint. |
| `mode` | no |  | exact (default on EVM and Starknet) or tolerance (default on Solana, where supply moves between slots). One of: `exact`, `tolerance`. |


## Wallet

### Account balance

`account.balance@1` · Wallet · native and token balance · evm, starknet, svm chains

A wallet's native balance (EVM) or token balance (ERC-20, Starknet token, or the wallet's associated SPL token account).

**Endpoint:** `GET /v1/{chain}/accounts/{account}/balance` · **MCP tool:** `get_balance`

| Parameter | Required | Default | Meaning |
| --- | --- | --- | --- |
| `account` | yes |  | the wallet. |
| `token` | no |  | the token (ERC-20, Starknet token, SPL mint); omit for the native balance on EVM chains. |
| `tokenProgram` | no | `spl` | Solana: the program that owns the mint, which decides the associated token account. One of: `spl`, `token2022`. |
| `mode` | no | `exact` | tolerance for a Solana account that changes between the nodes' reads. One of: `exact`, `tolerance`. |

**Returns:** the balance in whole tokens at the token's decimals (18 for native EVM balances); uint256, int256 in tolerance mode.

**Caveats:**

- Solana reads the wallet's associated token account only; tokens held in other token accounts are not counted, and a wallet without one fails the read.
- The Solana native balance (lamports) needs a source-format leaf that does not exist yet (Phase 2).

```bash
curl "https://data.molpha.io/v1/ethereum/accounts/0x9de443adc5a411e83f1878ef24c3f52c61571e72/balance?token=0x7f39c581f595b53c5cb19bd0b3f8da6c935e2ca0"
```
