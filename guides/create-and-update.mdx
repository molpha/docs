A Solana `Feed` account is only as fresh as its submitter keeps it. This guide shows how to keep one current with the SDK: subscribe, request rounds, submit them, and scale to many sources. Reading a feed needs no subscription; producing one does.

## 1. Subscribe

```ts
import { PlanType } from "@molpha/sdk";

const plan = await sdk.solana.getPlan(PlanType.Basic);

await sdk.solana.subscribe(PlanType.Basic, {
  maxPriceUsdc: plan.subscriptionPrice,
});

// Later: renew for another period
await sdk.solana.extendSubscription({
  maxPriceUsdc: plan.subscriptionPrice,
});
```

`maxPriceUsdc` is a safety bound: the transaction aborts if the on-chain price is higher than the user approved.

## 2. Derive `sourceId`

Source identity is deterministic. No separate creation transaction is sent.

```ts
import { deriveSourceIdString } from "@molpha/sdk";

const apiConfig = {
  url: "https://api.example.com/price",
  responseParser: "$.price",
};

const signaturesRequired = 3;
const sourceId = deriveSourceIdString(apiConfig);
```

`sourceId` is the keccak256 hash of the canonical `apiConfig`. The Solana `Feed` account is keyed by `(sourceId, signaturesRequired, submitter)`, and the first successful submit creates it if it does not exist.

For numeric values that move between fetches, use [tolerance mode](/concepts/feeds#exact-and-tolerance-mode).

## 3. Request and submit

```ts
const { result, signature, feed } = await sdk.requestAndSubmit({
  apiConfig,
  signaturesRequired,
});

const account = await sdk.solana.readFeed(sourceId, signaturesRequired);
console.log(account?.value, account?.timestamp.toString(), signature);
```

`requestAndSubmit` runs these two calls:

```ts
const result = await sdk.gateway.requestSignedData({
  apiConfig,
  signaturesRequired,
});

const { signature, feed } = await sdk.solana.submitAttestation(result);
```

If the round succeeds but the Solana submit fails, `requestAndSubmit` throws `SubmitFailedError`. The round is already paid for, so submit `error.result` again with `sdk.solana.submitAttestation` instead of requesting a new round.

## Constraints

- Subscription must be active.
- Requested quorum must be within the subscription's signer limit.
- A consumer other than the owner must be an active [delegate](/access-models/delegates).
- The gateway response must carry the `sourceId` derived from `apiConfig`; the SDK rejects a result that does not.
- A submitted update must have a strictly newer `timestamp` than the one stored in the `Feed` account.

## Fast repeated rounds

For repeated updates, cache registry selection config and nodes:

```ts
const context = await sdk.gateway.prepareContext();

const result = await sdk.gateway.requestSignedData({
  apiConfig,
  signaturesRequired,
  context,
});
```

### Several attestations in one transaction

`sdk.solana.submitAttestations(attestations)` submits several attestations of one feed (same `sourceId` and `signaturesRequired`, distinct timestamps) in one transaction, applied oldest first. The transaction is atomic. When the attestations do not fit, it throws `BatchTooLargeError` before sending; `error.fits` is how many do. See [Batch submit](/sdk/reference#batch-submit).

### Many sources at once

`requestMany` requests a list of sources and, by default, submits each attestation to Solana:

```ts
import { requestMany } from "@molpha/sdk";

const results = await requestMany(sdk, [
  { apiConfig, signaturesRequired, label: "price" },
  { apiConfig: otherApiConfig, signaturesRequired },
]);

for (const r of results) {
  if (!r.ok) console.error(r.label, r.error);
  else if (r.submitError) console.error(r.label, "signed but not submitted", r.submitError);
}
```

- The registry inputs are read once and shared by every request.
- Gateway concurrency is bounded. It halves when the gateway answers busy (HTTP 503 or 429) and grows back while requests succeed. Set the ceiling with `concurrency`.
- `spreadMs` spreads request starts over a window by a hash of each `sourceId`. The default is `0`, no spreading.
- `submit: false` skips the Solana submit. `submitConcurrency` bounds submits in flight (default 8).
- Results are returned in input order, and a source that fails does not stop the others. A failed submit keeps the signed `attestation` on the result and sets `submitError`.

Each request keeps the single-request retry policy described in the [gateway client](/sdk/gateway-api#retries-and-errors).
