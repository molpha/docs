---
title: "Delegates"
description: "Let a hot agent key request subscription-backed rounds under owner-defined caps."
---

A **Delegate** is the subscription-backed option for AI agents. The subscription owner keeps the cold key and prepaid plan; the agent holds a hot key that can authorize gateway rounds within a limit the owner sets on chain and the gateway enforces.

This is the alternative to [x402 pay-per-request](/access-models/x402). Use a delegate when someone already pays for a Molpha subscription and wants the agent to spend that quota — not when the agent should pay USDC per request.

## Use a delegate when

- A team already has an active subscription.
- The agent should not hold the owner's USDC or subscription key.
- You want a cap on how many rounds the agent can request.
- Rounds should be admitted by the gateway against the subscription and delegate request quota.

## On-chain account

```rust
#[account]
pub struct Delegate {
    pub owner: Pubkey,              // subscription owner
    pub delegate: Pubkey,           // hot agent authority
    pub max_data_requests: u64,     // round cap, enforced by the gateway
    pub bump: u8,
}
```

Seeds:

```text
["molpha_delegate", owner, delegate]
```

Create with `add_delegate` and remove with `remove_delegate`, which closes the account. There is no pause instruction. `add_delegate` requires an active subscription, a delegate key different from the owner, `max_data_requests` greater than 0, and a free slot under the subscription's `max_delegates`.

## Flow

1. Owner opens or extends a [subscription](/access-models/subscriptions).
2. Owner calls `add_delegate` with the agent pubkey and `max_data_requests`.
3. Agent (as `consumerAuthority`, with `subscriptionOwner` set to the owner) signs `RequestAuth` (`authSig` + `authTimestamp`, unix seconds) and calls `POST /v1/round/execute`; the gateway assigns the round's timestamp.
4. Gateway serves the signed payload.
5. The round counts against the subscription's `max_rounds` and the delegate's `max_data_requests` (see [Admission](/gateways/overview#admission)).

Where the gateway enables sign-in sessions ([`GET /v1/info`](/gateways/api/info) reports `sessionAuth: true`), the agent can request a [sign-in challenge](/gateways/api/session-challenge) that names its owner, sign it, exchange it at [`POST /v1/session`](/gateways/api/session-create), and send the bearer token instead of `RequestAuth`. Delegate access is still checked against chain state on every round.

The `sourceId` is the canonical API-config hash only. Owner and delegate requests for the same `apiConfig` share it. The consumer key is part of the gateway's replay identity, not of the source.

## Controls

| Control | Behavior |
| --- | --- |
| `max_data_requests` | Cap on this delegate's served rounds per subscription term, enforced by the gateway. The subscription's `max_rounds` also applies |
| Quorum | The subscription's `max_signers` applies to the owner and its delegates alike. A delegate has no quorum ceiling of its own |
| Removal | `remove_delegate` closes the account; the gateway stops admitting the key within seconds |
| Subscription expiry | The gateway rejects rounds if the subscription is inactive |
