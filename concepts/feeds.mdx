title: "Sources and feeds"
description: "A source is an API definition identified by its hash. A feed is the Solana account holding the latest verified value for a source."
---

Two terms appear throughout these docs:

- A **source** is an API definition: a URL, how to call it, and how to extract one value. It is identified by its `sourceId`, the hash of its canonical config.
- A **feed** is a Solana `Feed` account holding the latest verified value that one submitter wrote for a source at one quorum.

There is no feed-creation step. A source exists as soon as you define it, and a `Feed` account is created the first time someone submits an attestation for it.

## API config

```ts
const apiConfig = {
  url: "https://api.example.com/v1/finalized/price",
  method: "GET",              // default "GET"
  headers: {},                // default {}
  responseParser: "$.price",  // JSONPath to the value
  valueTransform: "",         // default ""
};
```

`aggregation` is optional and switches the source to [tolerance mode](#exact-and-tolerance-mode). All fields are listed in the [SDK reference](/sdk/reference#apiconfig).

## Source ID

```text
sourceId      = keccak256(canonicalJson)
canonicalJson = compact JSON of { url, method, headers, responseParser, valueTransform[, aggregation] }
                in exactly that key order, defaults filled in, header names sorted
```

- The same config gives the same `sourceId` for everyone, on every chain. It contains no owner, payer or quorum.
- The canonical form is **not** RFC 8785 (JCS). Derive it with the SDK (`deriveSourceIdString(apiConfig)`) or the MCP `derive_source_id` tool rather than hashing by hand: one differing byte gives a different source.
- The gateway and the nodes recompute it from the `apiConfig` you send, and the SDK rejects a response that names a different `sourceId`.

### Private configs

Only the `sourceId` reaches the chain. An API key can stay private: reference it as `{{secret.<name>}}` in the config and send the value encrypted for the nodes, so the gateway never sees it. Encrypted secrets work on subscription rounds only. See [Private APIs](/sdk/gateway-api#private-apis).

## Exact and tolerance mode

By default a round is **exact**: every signing node must fetch a byte-identical value. Design exact sources around settled data:

- Prefer finalized values over live-drifting ones.
- Avoid per-request timestamps, request IDs and unstable ordering in the response.
- Point `responseParser` at exactly the field you need.

For numeric values that move between fetches, use **tolerance mode**. The nodes share their observations, drop outliers and sign the median:

```json
"aggregation": {
  "mode": "tolerance",
  "rule": "median",
  "maxDeviationBps": 50,
  "maxAgeMs": 2000,
  "numeric": { "type": "int256", "decimals": 8 }
}
```

- `aggregation` is part of the `sourceId`, so a source's tolerance settings cannot change without changing its identity.
- The round needs `signaturesRequired` of at least 3.
- The signed value is a two's-complement `int256` scaled by `10^decimals`. Leave `valueTransform` empty.

## Values

The signed `value` is always 32 bytes. Its meaning is defined by whoever designs the source:

- Numeric sources should document their scale, for example `value / 10 ** 6`.
- A value longer than 32 bytes is signed as its `keccak256` hash. The submitter can pass the preimage (up to 256 bytes) to `submit_attestation`, which checks it and marks the feed `Hash`. The preimage is not stored.
- Decode a value only after verifying the attestation or validating the `Feed` account address.

## Solana feed account

```text
Feed PDA = ["molpha_feed", source_id, [signatures_required], submitter]
```

Each submitter maintains its own account for a source and quorum, so a reader decides whose feed it reads. The program re-verifies every write, so a submitter cannot change a value. It only chooses which attestations to submit and when.

| Field | Meaning |
| --- | --- |
| `source_id` | Source identifier |
| `value` | The signed 32-byte value |
| `value_kind` | `Value`, or `Hash` when `value` is the hash of a longer preimage |
| `submitter` | The account that writes this feed |
| `timestamp` | Unix milliseconds of the latest accepted attestation; strictly increasing |
| `signatures_required` | Quorum; fixed for the account |
| `signers_bitmap` | Signers of the latest attestation |
| `registry_version` | Registry version of the latest attestation; never decreases |

Reading a feed is free and needs no subscription. [Verify on Solana](/verifiers/solana) shows how to read one from TypeScript or from your own program.
