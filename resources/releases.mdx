## Roadmap

| Release | Status | Scope |
| --- | --- | --- |
| **Albyn** (A1) | Shipped, June 2026 | End-to-end signing and verification; verifiers on five testnets; first SDK |
| **Brebeneskul** (A2) | Shipped, July 2026 | Economic layer: USDC subscriptions, delegates, x402 pay-per-request, node deposits and rewards |
| **Chivchyn** (A3) | **Current**, October 2026 | Source-based attestations, versioned registry, epoch rewards, evidence-based slashing, 100 ms round grid, hosted MCP with wallet sign-in |
| **Dzembronia** (A4) | Next | Audit readiness: authority and access-control redesign, cross-chain registry synchronization, provider-signed data, subscription credits, monitoring and hardening |
| Mainnet | After A4 | External audit, then deployment on Solana mainnet, Starknet and an EVM chain. The node set stays permissioned, run by independent operators. |

Future scope and order can change.

## Chivchyn (A3)

**Protocol**
- A source is identified only by its `sourceId`, the hash of its canonical API config. There is no feed registration; `submit_attestation` creates a `Feed` per source, quorum and submitter on first write.
- The signed object is an `Attestation`: payload plus aggregate signature, with a 141-byte signed message.
- Every registry change creates an immutable snapshot; a superseded version stays valid for a grace period.
- Round timestamps are unix milliseconds on a fixed 100 ms grid assigned by the gateway; requests for one source and quorum in the same tick share a round.
- Median tolerance mode for numeric sources that move between fetches.

**Economics**
- Rewards are paid per epoch from a pool funded by subscriptions and x402 payments, using sampled rounds (tickets) as participation evidence. There is no per-round settlement.
- x402 payments go straight to the protocol treasury; there is no escrow account.
- Nodes post a USDC deposit. `slash_offence` punishes equivocation, unsolicited signing, commitment reuse and nonce reuse with on-chain evidence, and freezes inactive nodes.

**Developer tools**
- SDK: `requestSignedData`, `requestAndSubmit`, batch submits (`submitAttestations`) and `requestMany`.
- EVM and Starknet verifiers: `verify(attestation, maxAge)` returns `(success, code)` and never reverts on rejection.
- MCP server: hosted at `mcp.molpha.io` with Sign-In-With-X sessions and wallet-signed x402 payments, or local over stdio.
- Integrated data providers and x402-paywalled API sources.

**Deployments**: Solana program `MoLF3pgVA9MENSuEujxNNSMaTo71aLyewaH5nrWfUZs` on devnet; EVM verifier `0xA6e49A3A1caf3E110cC04765B934C8FF118C2568` on Ethereum Sepolia, Arbitrum Sepolia, Avalanche Fuji and BNB Chain testnet; Starknet verifier `0x032b9f47f12189668b94a5d62fb7d60f968ed0dbaf22090649d1d7a91d79cc38` on Sepolia. Packages: `@molpha/sdk` 0.2.0 and `molpha-verifier` 0.3.0. See [Deployments](/verifiers/deployments).

## Brebeneskul (A2)

- USDC plans and subscriptions, delegates for agent keys, and x402 pay-per-request.
- Gateway settlement with dispute and finalize windows, node staking and reward accounting.
- Solana program `MoLFGDpFoVnQgwbkTNScKPohCxhbfd61JjFrnotuwzh`.

## Albyn (A1)

- First public testnet release: full signing and verification flow.
- Solana program `MoLFeTRpDZgckPjjbLwW1wB9n85bQiqboPnvw9RwoG8`; EVM verifiers on Ethereum Sepolia, Arbitrum Sepolia, Avalanche Fuji and BSC testnet; Starknet verifier on Sepolia with cross-chain parity tests.
- SDK published as `@molpha-oracle/sdk`, later renamed `@molpha/sdk`.
