Every public export of `@molpha/sdk`, grouped by area. For usage, see the [SDK overview](/sdk/overview) and the [gateway client](/sdk/gateway-api). Hex strings are lowercase without `0x` unless noted.

## Clients

### `MolphaSDK`

```ts
new MolphaSDK(opts: MolphaSDKOptions)
```

| Member | Type |
|---|---|
| `gateway` | [`MolphaGateway`](/sdk/reference#molphagateway) |

### `MolphaGateway`

#### Submit options

`SubmitAttestationOptions`:

| Option | Default | Meaning |
|---|---|---|
| `computeUnitLimit` | `estimateSubmitComputeUnits(signerCount)` | Compute-unit limit. |
| `priorityFeeMicroLamports` | none | A number, or `"auto"` for the 75th percentile of recent fees on the feed, capped at 1 lamport per unit. |

### Batch submit

```ts
const { signature, feed, count } = await sdk.solana.submitAttestations(attestations);
```

Sends one `submit_attestation` instruction per attestation, in timestamp order, in one transaction.

- All attestations must share `sourceId` and `signaturesRequired` and have distinct timestamps. Registry version and signer set may differ.
- The transaction is atomic: if one instruction fails (typically because a newer value landed first), none applies.
- `rawValue` is not supported; submit those with `submitAttestation`.
- If they do not fit in one transaction, it throws `BatchTooLargeError` before sending.
- `opts` takes `computeUnitLimit` and `priorityFeeMicroLamports` (`SubmitAttestationsOptions`).

Sizing helpers:

| Function | Returns |
|---|---|
| `maxAttestationsPerTransaction(signerCount, { distinctSigners?, priorityFee? }?)` | How many attestations with that many signers fit in one transaction. |
| `estimateSubmitTransactionSize(count, signerCount, { distinctSigners?, priorityFee? }?)` | Serialized transaction size, in bytes. |
| `estimateSubmitComputeUnits(signerCount)` | Compute-unit limit for one submit. |
| `estimateSubmitBatchComputeUnits(signerCounts)` | Compute-unit limit for a batch. |
| `SUBMIT_INSTRUCTION_DATA_BYTES` | `234`, instruction data size without a raw value. |

### `requestMany`

```ts
requestMany(sdk: MolphaSDK, feeds: BulkFeed[], opts?: BulkOptions): Promise<BulkResult[]>
```

Updates many feeds. Reads the registry once, bounds concurrency adaptively (halves on 503/429, grows on success) and runs Solana submits on a separate limiter. Results come back in input order, and one feed failing does not stop the others.

| `BulkOptions` | Default | Meaning |
|---|---|---|
| `concurrency` | half the gateway's `maxInflightRounds` (max 64), or 32 | Ceiling on gateway requests in flight. |
| `spreadMs` | `0` | Spread request starts over this window by a hash of the `sourceId`. |
| `submit` | `true` | Submit each attestation to Solana. |
| `submitConcurrency` | `8` | Solana submits in flight. |
| `request` | none | `RequestSignedDataOptions` applied to every feed, except `apiConfig`, `signaturesRequired` and `context`. |
| `onResult` | none | Called as each feed finishes. |
| `signal` | none | `AbortSignal`; stops starting new feeds. |

`BulkFeed` is `{ apiConfig, signaturesRequired, label? }`. `BulkResult` has `index`, `label?`, `ok` (round succeeded), `attestation?`, `signature?`, `feedAddress?`, `error?` and `submitError?`; `attestation` is kept when only the submit failed. Also exported: `AdaptiveLimiter` and `spreadOffsetMs(sourceIdHex, spreadMs)`.

## Request and result types

### `RequestSignedDataOptions`

```ts
interface RequestSignedDataOptions {
  apiConfig: APIConfig;            // determines sourceId; pass the same config every time
  signaturesRequired: number;      // u8; tolerance mode requires >= 3
  subscriptionOwner?: string;      // base58; MolphaSDK default: wallet public key
  consumerAuthority?: string;      // base58; default: subscriptionOwner
  signer?: Signer;                 // RequestAuth signer for this call
  encrypt?: { secrets: Record<string, string> };
  sourcePayment?: SourcePaymentOptions;
  maxAge?: number;                 // seconds, default 60
  maxRetries?: number;             // attempts, default DEFAULT_MAX_RETRIES (6)
  timeoutMs?: number;              // per request, default DEFAULT_ROUND_TIMEOUT_MS (35000)
  context?: Partial<RoundContext>; // any field present skips its fetch
  verifyNodeKeys?: NodeKeyVerifier;
  allowUnverifiedNodeKeysForPrivateApi?: boolean; // unsafe, default false
}
```

Behaviour of each option is described in [`requestSignedData`](/sdk/gateway-api#requestsigneddata).

### `APIConfig`

```ts
interface APIConfig {
  url: string;
  method?: "GET" | "POST" | "PUT"; // canonical default "GET"
  headers?: Record<string, string>; // canonical default {}, keys sorted
  responseParser: string;
  valueTransform?: string;          // canonical default ""
  aggregation?: AggregationConfig;  // omit for exact mode
}

interface AggregationConfig {
  mode: "tolerance";
  rule: "median";
  maxDeviationBps: number;          // u32, deviation from the lower median
  maxAgeMs: number;                 // positive integer, max observation age
  numeric: NumericConfig;           // { type: "int256"; decimals: number } (0..255)
}
```

Without `aggregation`, every signer must fetch the identical value. With it, the selected nodes exchange signed observations, drop stale ones and outliers beyond `maxDeviationBps`, and sign the lower median of `signaturesRequired` surviving values as an `int256` scaled by `10^decimals`. `aggregation` is part of the `sourceId` and needs `signaturesRequired >= 3` (`MIN_TOLERANCE_SIGNATURES`). `mode: "exact"` is rejected with `AggregationConfigError`.

### `RoundContext`

```ts
interface RoundContext {
  registryVersion: number;
  redundancyBuffer: number;
  nodeCount?: number; // Registry.node_count of the snapshot
  nodes: Node[];      // full node set of the registry version
}
```

Returned by `prepareContext()`. `RegistrySelectionConfig` is the same without `nodes`.

### `Attestation`

A completed round. `payload` and `signature` are signed; `value` and `fresh` are gateway metadata. Field meanings and the signed message are in [attestations](/concepts/attestations).

```ts
interface Attestation {
  payload: AttestationPayload;
  signature: SchnorrSignature;
  value: string;   // human-readable value, not signed; for tolerance mode, payload.value at numeric.decimals
  fresh: boolean;  // true for live rounds
}

interface AttestationPayload {
  value: string;              // 32 bytes, hex: the signed value
  sourceId: string;           // 32 bytes, hex
  registryVersion: number;
  signaturesRequired: number;
  timestamp: number;          // unix milliseconds, assigned by the gateway
}

interface SchnorrSignature {
  s: string;                  // 32-byte scalar, hex
  commitmentAddr: string;     // 20-byte commitment address, hex
  signersBitmap: string;      // 32-byte big-endian bitmap, hex
}
```

## Verifier arguments

### `buildEvmVerifierArgs`

```ts
import { buildEvmVerifierArgs, parseEvmVerifyResult, MOLPHA_VERIFIER_ABI } from "@molpha/sdk";

const { attestation, maxAge } = buildEvmVerifierArgs(result, { maxAge: 60 });
```

Maps an `Attestation` onto `verify(Attestation calldata, uint64 maxAge)` of the [EVM verifier](/verifiers/evm). `maxAge` (seconds) is required; `0` disables the freshness check. Integers are range-checked against their Solidity types (`RangeError`).

`signature.s` becomes `signature.signature` and `commitmentAddr` becomes `commitment`; `timestamp` and `signersBitmap` become `bigint`. The full struct layout is on the [EVM verifier](/verifiers/evm) page.

| Export | Purpose |
|---|---|
| `MOLPHA_VERIFIER_ABI` | `verify` plus the read-only registry views. |
| `encodeEvmVerifyCalldata(args)` | Calldata for a raw `eth_call`. |
| `parseEvmVerifyResult(result)` | Raw return data or a decoded tuple to `{ success, code, reason }`. Throws if `success` and `code` disagree. |
| `toFixedHex`, `signersBitmapToUint256`, `signersBitmapToDecimal` | Conversions. |
| Types | `EvmVerifierArgs`, `EvmAttestation`, `EvmAttestationPayload`, `EvmSchnorrSignature`, `EvmVerifyResult`, `BuildEvmVerifierArgsOptions`, `MolphaEvmNetwork` |

### `buildStarknetVerifierArgs`

```ts
import { buildStarknetVerifierArgs, encodeStarknetVerifyCalldata } from "@molpha/sdk";

const args = buildStarknetVerifierArgs(result, { maxAge: 60 });
const calldata = encodeStarknetVerifyCalldata(args); // 13 felts, Cairo Serde order
```

Maps an `Attestation` onto `verify(attestation, max_age)` of the [Starknet verifier](/verifiers/starknet). `maxAge` is required, in seconds; `0` disables the freshness check.

Field names become snake_case, 32-byte values become `u256` (`bigint`) and the commitment address becomes a `felt252`. The struct and calldata layout are on the [Starknet verifier](/verifiers/starknet) page.

| Export | Purpose |
|---|---|
| `parseStarknetVerifyResult(result)` | Two felts or a decoded tuple to `{ success, code, reason }`. |
| `commitmentAddressToStarknetFelt`, `signersBitmapToStarknetUint256` | Conversions. |
| `getMolphaStarknetVerifierAddress(network)`, `MOLPHA_VERIFIER_STARKNET_ADDRESSES` | Verifier address by network (`"starknet-sepolia"`). |
| Types | `StarknetVerifierArgs`, `StarknetAttestation`, `StarknetAttestationPayload`, `StarknetSchnorrSignature`, `StarknetVerifyResult`, `StarknetFeltLike`, `BuildStarknetVerifierArgsOptions`, `MolphaStarknetNetwork` |

### Result codes

`VERIFY_CODES` maps the names of the codes both verifiers return (`OK` = 0 through `STALE` = 10) to their numbers; the [EVM verifier](/verifiers/evm) page explains each one. `verifyCodeName(code)` returns the name, or `undefined` for a code this SDK does not know. Types: `VerifyCode`, `VerifyCodeName`.

## Errors

| Class | Thrown when | Fields |
|---|---|---|
| `GatewayError` | The gateway refused or failed a request, or its response is malformed or does not match the request. | `status?: number` |
| `SubmitFailedError` | `requestAndSubmit` got an attestation but the Solana submit failed. | `result: Attestation`, `cause` |
| `UpstreamPaymentRequiredError` | The API source is paywalled and there is no `sourcePayment`, or the source refused the payment. | `quote: UpstreamQuote` |
| `BatchTooLargeError` (a `RangeError`) | `submitAttestations` got more than fits in one transaction. Nothing was sent. | `fits` (how many fit, oldest first), `size`, `limit`, `count` |
| `AggregationConfigError` | `apiConfig.aggregation` is invalid, or tolerance mode has fewer than 3 signers. | none |

Which HTTP statuses are retried is in [retries and errors](/sdk/gateway-api#retries-and-errors).
